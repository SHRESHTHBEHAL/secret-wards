404FoundUs · Raksha: a measured privacy firewall for Indian hospital records

Track 3 · Secret Wards · Members: Shreshth Behal, Harman Manik · Repo: github.com/SHRESHTHBEHAL/secret-wards
Pitch. Raksha learns every identity from every file first, then scrubs it from every channel, in 11 Indian scripts, keeps each medical value exact, links patients with keyed pseudonyms that never merge namesakes, and tunes its privacy policy against a replica of the published attacker rather than by guesswork.

1. In one paragraph

A plain PII tool looks for names in one document at a time and in one script. Raksha works on the whole dump: a first pass harvests identity facts (names, relatives, IDs, phones, addresses) from all 4 hospitals' CSV, JSON, FHIR and notes; a linker turns them into patients; a privacy planner decides each patient's age band, geography and date shift; only then is anything written. Because every detector runs on a script-folded copy of the text, the same rules read Hindi, Hinglish, Bengali, Punjabi, Gujarati, Odia, Tamil, Telugu, Kannada, Malayalam and Urdu, and a final leak gate re-checks every output channel (content, file names, JSON keys, CSV headers, base64, the report itself) against everything learned anywhere. No LLMs, no models, offline, CPU; standard library plus optional rapidfuzz.

3. How it works

  • Ingestion. Format from content, not extension; UTF-8, BOM, UTF-16 with or without BOM, cp1252; large base64 fields, NaN and blank header lines handled. Truncated, empty, binary, PDF, XML, over-deep JSON and escaping symlinks are quarantined and never copied.
  • Detection. Field typing by word stems and value shapes (an unlabelled, near-unique, ID-shaped column is an identifier). Layered free-text rules: Aadhaar (Verhoeff), ABHA, PAN, UHID/IPD/OPD, phones in any format and digit script; labels, kinship anchors (S/o, W/o, पति, ਪਤੀ, తండ్రి), honorifics (ji, sahab, garu); addresses and place phrases ("ghar X mein hai"); names in export paths. Protected clinical spans (doses, 1-0-1, vitals, labs, eponyms, doctor lines, wards) resolve the meaning traps: C/O fever stays, C/O Ramesh goes, Dr. Ramesh stays.
  • Multi-script. Brahmic Unicode blocks share Devanagari's layout at a fixed offset, so text is folded onto Devanagari one code point for one (Urdu by a phonetic table). Spans on folded text index the original exactly.
  • Linkage & pseudonyms. Phonetic name keys (aspirates, vowel length, w/v, Mohammad/Md) with bounded edit distance; rules from strong IDs down to name + DOB / relative / village + age; cannot-link on gender, DOB, Aadhaar, ABHA, PAN, birth year checked on whole groups, so chains never over-merge; weak evidence gives null. PSN- IDs are HMAC-SHA256 under a derived subkey and never contain the patient's own ID digits.
  • Privacy layer. DOB removed; one 10-year band per patient; district and PIN prefix only in cells of ≥ 3 patients; per-patient shifts of 30-180 days with no two patients on one offset; FHIR meta dates shifted too.

4. USP

  • Learn once, scrub everywhere. An ID seen in a registration CSV is removed from a nurse's note, a file name, a JSON key and a base64 attachment in another hospital's export.
  • 11 scripts from one rule set, by length-preserving script folding: on native-script clinical notes PII leaks fell from 22/32 to 0/32 with every dose and doctor kept, and practice output stayed byte-identical.
  • Measured privacy. A replica of the published attacker (A1-A7) chose every policy number below; collision-free shifts remove the attacker's global-shift recovery outright.

On data we did not tune on (renamed columns, new names and villages, new ID and date formats, new scripts): five held-out sets (two fresh synthetic datasets, three "chaos" rewrites of the practice set) all leak 0.0% with linking F0.5 1.00 and 98.5-99.5% of medical values kept. On a composite of the published scoring formulas Raksha scores 98.2-98.4; as a ceiling reference, a frontier LLM doing the same job by hand (forbidden by the rules) scored 94.5 in 342 s and is not deterministic.

Why these settings. Exact doses, labs and stay lengths are the research value, so they are never touched; we pay instead with age and geography detail, and only where the measured cell is small. Rare diagnoses stay: removing them bought almost no privacy for a large clinical loss.

6. Security design

  • No data at rest outside the release: all intermediate data lives in memory; no temp files, caches or logs (a test runs with empty TMPDIR/HOME and asserts they stay empty).
  • Keys away from data: RAKSHA_SECRET comes from the environment, is expanded into HMAC subkeys and is never written; the key object hides its value and refuses to be pickled.
  • PII-free logs and errors: stderr carries only the exception class and stage. A crash still writes a valid report; quarantined files appear only as SHA-256 + reason code.
  • Assume breach: the release is designed to be safe to leak, and releases under different secrets cannot be linked (cross-release risk 0%).

7. Known limitations

  • The targeted attack still succeeds for about 43% of known-fact targets: rare diagnoses and exact stay lengths remain by design. Next step: coarsen only the few profiles the replica attacker still re-identifies.
  • Tamil lacks voiced consonants and Urdu omits short vowels, so a few cross-script names key differently; linking then abstains rather than guesses.
  • A capitalised phrase after "near" can be taken for a person ("near Optic Disc"): a small over-redaction.
  • 10-year bands are coarser than some studies want; it is one line in config/policy.yaml.
